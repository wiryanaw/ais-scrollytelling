01 The Problem

53% of students said the interface was unattractive. Most just gave up.

PUSTIPANDA launched the Academic Information System in 2010. By 2022, the interface had barely changed. Prior heuristic evaluation studies and a survey of 25 students (Zulfallah & An Najjar, 2018) confirmed what students already knew.

"The AIS web interface is not user-friendly and PUSTIPANDA has not paid attention to the UI and UX aspects of the system at all."

Six recurring pain points surfaced

📅
Academic Year Input
Students had to manually calculate which year mapped to their semester — no guidance, no default.
🔀
Unordered Scholarships
Opportunities were listed randomly with no deadline sorting — impossible to see what was still open.
🔒
No Login Error Message
Wrong NIM or password produced silence — users were left confused about what failed.
🔤
Small Typography
Font sizes were too small. Grade notation mixed text ("SB") and numbers with no legend.
↩️
No Cancel Controls
Editing personal data offered no Cancel or Back button — users got trapped in forms.
🎨
Flat Visual Design
No icons, no visual hierarchy, no personality. Described as "too plain and bare" by participants.
02 The Research Method

User-Centered Design:
letting users lead every decision

Unlike traditional development that builds first and tests later, UCD begins with listening to people — and returns to them at every stage. Four phases, repeated iteratively until the design works.

01 / Specify Context
Who uses AIS, and how?
Interviews and observations mapped real usage — who logs in, on what device, for which tasks — before any assumption was made.
02 / Specify Requirements
What must the system do?
User needs from phase one were turned into concrete design requirements — an explicit list binding every decision.
03 / Produce Solutions
Wireframes → prototypes
Information architecture first, then wireframes, then a high-fidelity prototype in Figma ready for real testing.
04 / Evaluate
Did it actually improve?
A second round of usability testing with the same participants measured whether the redesign solved each identified problem.

How usability was measured

Three complementary techniques measured usability across the three ISO 9241-11 dimensions.

Dimension Technique What it captures
Effectiveness Performance Measurement — Task Completion Rate Did users successfully finish each task? Binary: 1 (success) or 0 (fail).
Efficiency Performance Measurement — Execution Time How long (in seconds) did each task take to complete?
Satisfaction System Usability Scale (SUS) + Verbal Behavior Analysis 10-item SUS questionnaire (0–100 score) plus categorized spoken comments from think-aloud.

Understanding the user — persona synthesis

Interviews and observations were synthesized into a representative persona. Every design decision was checked against this person's needs.

🎓
Diah, 22
Active student · Tangerang · Multi-device · UIN Jakarta
  • Needs icons on menus to understand features without reading every label
  • Needs a clear error message when login credentials are wrong
  • Needs course registration that doesn't require remembering academic years
  • Needs scholarships sorted by deadline so she can see what's still open at a glance
  • Opens AIS roughly twice per semester — for KRS registration and grade checking
  • Confused by page errors, unsorted lists, and forms with no cancel option
03 The Design

Eight requirements.
One redesigned system.

From Diah's needs — and those of four other participants — eight requirements drove every design decision, from information architecture to the final high-fidelity prototype in Figma.

#User NeedDesign Requirement
1Understand menus at a glanceAdd icons to all sidebar navigation items
2See key info without huntingDashboard consolidating GPA, active semester, and open scholarships
3Know when login failsInline error message on wrong NIM or password
4Register courses without confusionDirect semester picker — drop the academic year text input entirely
5Find past academic activity easilyReplace year input with simple semester dropdown, pre-populated
6Know which scholarships are availableSort by deadline, show open/closed badge on each listing
7Cancel editing personal dataAdd Cancel and Back controls to every edit form
8Interface that feels modernUpdated visual language: larger type, consistent spacing, clear hierarchy

Conclusion

Good design isn't decoration.
It's respect for the user's time.

This research demonstrated that a structured, evidence-based redesign process — one that begins by listening to real users — can transform an interface students dread into one that actually helps them succeed academically.

The gains weren't superficial. Task completion rose 18%. Efficiency improved 18%. Satisfaction jumped 56 points. Negative comments fell 42%. These numbers represent thousands of students spending less time fighting a broken portal, and more time focused on their studies.
